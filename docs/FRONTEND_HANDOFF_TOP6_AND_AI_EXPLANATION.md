# Frontend Handoff: Top-6 Match Shortlist & AI Fit Explanation

This document provides complete, self-contained implementation instructions for the frontend team (`kidcarematch-frontend`) following the backend optimizations implemented in Spec #98 (Tickets #99, #100, #101, and #102).

---

## 1. Executive Summary

The backend matching and commute services have been optimized to reduce external OneMap routing call volume, standardize recommendation sizes, and provide comparative ranking transparency:

1. **Top-6 Shortlist Standardization**: The backend multi-criteria matching engine defaults to `top_n = 6` (and bounds Stage 1 spatial candidate routing to `STAGE1_MAX_CANDIDATES = 15`). The frontend must update match request payloads from `top_n: 10` to `top_n: 6`, slice candidate results to 6, and update UI copy to `"Top 6 matches"`. This directly cuts per-card `POST /api/v1/centres/{centre_id}/commute` queries from 10 down to 6 (a 40% reduction in downstream commute traffic).
2. **Explicit AI Fit Explanation Labeling**: The match explanation banner must explicitly communicate that recommendations and rankings are generated by AI (e.g. badge/eyebrow `"AI FIT EXPLANATION"` and heading `"AI Fit Explanation — Why these matches & ranking"`).
3. **Comparative `ranking_rationale` Rendering**: The `FitExplanationResponse` contract now includes `ranking_rationale: string` (and `fallback_used?: boolean`). The frontend must display `explanation.ranking_rationale` directly beneath `explanation.summary_narrative` so parents can see the comparative trade-offs explaining why the centres are ranked in order `#1` through `#6`.

## 2. API Contract Updates

### 2.1 `POST /api/v1/centres/match` Request Payload

Update the request payload in `src/api.js` or wherever `matchCentres` is dispatched:

```typescript
export interface CentreMatchRequest {
  profile_id?: string;
  level?: PreschoolLevel;
  home_postal_code?: string;
  workplace_postal_code?: string;
  monthly_household_income?: number;
  per_capita_income?: number;
  preferred_budget?: number;
  vacancy_weight?: number; // 1 to 5 (default 3)
  cost_weight?: number;    // 1 to 5 (default 3)
  travel_weight?: number;  // 1 to 5 (default 3)
  applicant_status?: "WORKING_APPLICANT" | "NON_WORKING_APPLICANT";
  top_n?: number;          // Default is now 6 (allowed 1 to 20)
}
```

**Required Change**: Change `top_n` from `10` to `6`:
```javascript
// Example in src/main.jsx:
const response = await matchCentres({ profile_id: savedProfileId, top_n: 6 });
```

### 2.2 `FitExplanationResponse` Response Schema

Update the TypeScript / JSDoc interface for `FitExplanationResponse`:

```typescript
export interface FitExplanationResponse {
  /** Synthesized narrative explaining multi-criteria search trade-offs */
  summary_narrative: string;
  /** Deep-dive rationale explaining why the top-ranked centre was recommended */
  top_centre_rationale: string;
  /** Comparative explanation of why the shortlisted candidates are ordered in their specific sequence */
  ranking_rationale: string;
  /** Concise 1-sentence highlight for each candidate in top results */
  candidate_highlights: string[];
  /** Indicates whether the deterministic fallback explanation was used instead of Gemini AI */
  fallback_used?: boolean;
}
```

#### What `ranking_rationale` Contains
- **Comparative Multi-Criteria Narrative**: 2–4 sentences comparing candidate centres across **Overall Fit**, **Vacancy Fit** (available vs limited vs full), **Cost Fit** (net Estimated Monthly Payable Fee after subsidies), and **Travel Fit** (Commute Deviation or distance).
- **Explicit Rank Progression**: Outlines why Centre #1 beat Centre #2, why Centre #2 beat Centre #3, etc.
- **Resilient Fallback**: Always guaranteed to be non-empty and well-formed. Even when external AI quotas or network errors occur, the backend deterministic fallback populates `ranking_rationale` (with `fallback_used: true`).

## 3. Frontend Implementation Checklist

### 3.1 Update Match Request & Result Slicing

**Target Files**: `src/main.jsx`, `src/api.js`

1. **Payload `top_n: 6`**:
   Ensure `matchCentres` is called with `top_n: 6`:
   ```javascript
   const response = await matchCentres({ profile_id: savedProfileId, top_n: 6 });
   ```
2. **Shortlist Slicing**:
   Ensure candidate lists are sliced to 6:
   ```javascript
   const ranked = matchCandidates.slice(0, 6);
   ```
3. **Card Commute Reduction**:
   Passing `ranked` (length $\le 6$) into `<MatchesCommute centres={ranked} ...>` ensures the frontend only dispatches at most 6 parallel `/commute` calls instead of 10.
4. **Header Copy**:
   Update any remaining header copy to reference 6 matches:
   ```jsx
   <h2>Top 6 matches for your family</h2>
   ```

### 3.2 Update Fit Explanation Banner Header & AI Label

**Target File**: `src/main.jsx` (around `.match-explanation-summary`)

The banner should clearly inform parents that this explanation is AI-synthesized.

**Recommended JSX Markup**:
```jsx
{ranked.length > 0 && (summaryNarrative || rankingRationale) && (
  <section
    className="match-explanation-summary"
    aria-labelledby="match-explanation-heading"

  </section>

```

### 3.3 Extract & Sanitize `ranking_rationale`

```javascript
const matchExplanation = matchRun?.explanation;
```
