# Admin Portal and Operations Architecture

## Context

KidCareMatch requires comprehensive administrative and operational capabilities to maintain system integrity, oversee user accounts, moderate community reviews, configure government childcare subsidy rules, and monitor automated external data synchronizations (ECDA and OneMap). Because administrative actions carry elevated privileges, the system demands strict role-based access control (RBAC), consistent API routing conventions, and robust operational observability while maintaining architectural alignment with existing federated Firebase authentication.

## Decisions

1. **Modular Sub-Package Routing Under `/api/v1/admin`**: Administrative endpoints are organized into dedicated domain modules within `kidcarematch_backend.api.v1.admin` (`auth`, `users`, `reviews`, `subsidy_rules`, `sync`, `status`). The aggregated admin router is mounted in the root application (`main.py`) under the canonical prefix `/api/v1/admin`, ensuring complete separation between public/parent APIs and privileged administrative routes.
2. **Stateless Administrative Session Verification**: Administrator session verification (`POST /api/v1/admin/auth/login`) validates the incoming Firebase ID token against the database, asserting that the corresponding `User` entity has role `ADMIN` and status `ACTIVE`. Successful authentication yields the administrator's profile information (`user_id`, `email`, `full_name`, `role`, `account_status`, `admin_level`). Session termination (`POST /api/v1/admin/auth/logout`) provides a standard HTTP 200 OK contract acknowledging client session teardown.
3. **Strict Authorization Guards**: Administrative routes enforce dual validation: missing, expired, or malformed Bearer tokens trigger HTTP 401 Unauthorized (`get_token_claims`), while authenticated accounts with insufficient privileges (e.g., role `PARENT`) or suspended status (`AccountStatus.SUSPENDED`) trigger HTTP 403 Forbidden (`get_current_admin`).
4. **Canonical Account Deactivation Semantics**: Administrative account deactivation transitions users to `AccountStatus.SUSPENDED` rather than performing destructive hard-deletions. Suspended accounts preserve relational referential integrity across historical records (preschool reviews, preference profiles, and vacancy watchlists) while immediately revoking platform authentication and API access.
5. **Operational Monitoring and Heartbeat Observability**: Asynchronous background sync jobs and external integration health (ECDA datasets, OneMap API, data.gov.sg) are tracked via persistent `ExternalDataSourceStatus` records. Administrative endpoints provide observability into pipeline states (`IDLE`, `RUNNING`, `SUCCESS`, `FAILED`), execution timestamps (`last_successful_sync`, `last_attempted_sync`), record throughput counts, and diagnostic failure messages.
