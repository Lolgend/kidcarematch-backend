# Separate Centre-Detail Commute Display Contract from Matching

Centre-detail commute comparisons require decoded route geometry, selectable travel modes (`drive`, `pt`, `walk`, `cycle`), representative weekday/weekend sample pairs at 08:00 SGT, sequential public-transport departure timing, and explicit `unavailable` states when OneMap cannot resolve a postal code or route. We expose these through dedicated endpoints (`GET /api/v1/centres/{centre_id}/location` and `POST /api/v1/centres/{centre_id}/commute`) backed by a strict commute adapter (`core/commute.py`), while leaving the existing multi-criteria matching adapter (`core/onemap.py:get_route_duration_and_distance` and `POST /api/v1/centres/match`) unchanged. Reusing the matching adapter directly would either misrepresent straight-line Haversine fallbacks as routed map journeys in the UI or alter candidate ranking semantics mandated by ADR-0007.
